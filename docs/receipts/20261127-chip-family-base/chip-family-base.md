# 芯片族 profile 作为基类 + 项目适配副本（2026-11-27）

## 口径（用户确认）
> 公用的先拿来适配，适配后放自己项目下面，就是符合当前项目+芯片的 profile。
> 芯片族的不变，芯片族等于基类。
> 大品类是同一个可以公用一套 profile。比如美的和 TCL 都是 CSK7，CSK 串口日志可以通用一套。
> 有个别的可以实时修改，影响不大。主要芯片一样的话，大概率都能通用。

## 结构
- 基类：芯片族的端口角色、波特率、日志行格式、标记位正则；稳定，不随单个项目改动
- 派生：项目把基类取来适配，结果放在自己项目目录，形成「当前项目 + 芯片」的 profile
- 基类升级不回写项目；项目需要时重新适配

## 实例：设备改名
- 原设备名「奥普001」→ 实际固件为「纯离线天猫精灵_csk3022」，芯片 CSK3022
- 同一台机器改名，端口与标记未变：A=COM6@115200（ap 日志）、C=COM3@115200（协议）、
  control=COM5@115200（上下电回执）
- 历史证据目录保留旧名不改写

## 风险与对策
项目从基类复制后不再跟踪基类，基类改进时无法判断哪些项目已落后。
对策：项目 profile 记录来源基类标识与校验值（base_profile / base_sha256），
基类变更后可据此列出待重新适配的项目。
